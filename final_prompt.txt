You are a software engineer.

You are given a minimal Flask-like framework skeleton in miniapp.py and a fixed test suite in test_routes.py.
The framework supports:
- @app.route(...) route registration
- Blueprint routes and app.register_blueprint(bp, url_prefix=...)

Your task is to implement a NEW FEATURE: Route Manifest + Conflict Analysis.

You MUST deliver:
1) An implementation of MiniApp.route_manifest() in miniapp.py
2) A runnable one-command test script: run_tests.sh
3) A README.md

You MAY add additional automated tests (new test files), if you believe they improve correctness.
You MUST NOT modify test_routes.py.

-----------------------
Feature Requirements
-----------------------

Implement MiniApp.route_manifest() to return a JSON-serializable dict with these top-level keys:

- "routes": a list of route entries, one per registered route
- "conflicts": a list of conflict/override findings
- "summary": aggregate counts to support quick inspection

Each route entry MUST include at least:
- method (string)
- path (string)
- endpoint (string)
- source (string or null)
- blueprint (string or null)
- order (int)  # registration order

Conflict detection requirement:
- A conflict occurs when two or more routes share the same (method, path).
- The manifest must include an entry in "conflicts" for each conflicting (method, path).
- Each conflict entry MUST include at least: method, path, and a list of the involved routes (by order or endpoint).

Determinism requirement:
- "routes" must be sorted in a stable deterministic way (registration order is acceptable).
- "conflicts" ordering must also be stable.

The provided tests check only a minimum baseline.
Your implementation must be useful beyond the tests, but does not need to match Flask internals.

-----------------------
Deliverables: run_tests.sh and README.md
-----------------------

run_tests.sh:
- Must be executable
- Must install pytest if needed (using python -m pip)
- Must run the full test suite (including any extra tests you add)
- Must exit non-zero on failure
- Must print a short summary at the end (pass/fail)

README.md:
- Explain what Route Manifest is, what problem it solves
- Document the JSON schema at a high level (keys + meaning)
- Provide at least one example manifest output snippet
- Explain how to run: ./run_tests.sh
- Keep it technical and concise

-----------------------
Self-check requirement (for human review)
-----------------------

After implementing, you must:
- Run ./run_tests.sh
- Include the command and a short excerpt of output in your final response (enough to show tests ran)

Success criteria:
- All tests pass.
- The manifest is structured, deterministic, and useful for debugging route registration and conflicts.
- README.md enables a reviewer to quickly evaluate the output quality.
