-----------------------
Feature Requirements
-----------------------

Implement MiniApp.route_manifest() to return a JSON-serializable dict with these top-level keys:

- "routes": a list of route entries, one per registered route
- "conflicts": a list of conflict/override findings with severity levels
- "warnings": a list of potential issues (e.g., ambiguous patterns, unused routes)
- "pattern_analysis": analysis of route patterns and their complexity
- "summary": aggregate counts including conflict severity distribution

Each route entry MUST include at least:
- method (string)
- path (string)
- endpoint (string)
- source (string or null)
- blueprint (string or null)
- order (int)  # registration order
- path_params (list of strings)  # extracted from <param> or :param patterns
- is_dynamic (boolean)  # whether the route contains path parameters
- complexity_score (float)  # calculated based on path structure

Conflict detection requirement (ENHANCED):
- EXACT conflict: Two or more routes share the same (method, path) exactly - severity: "critical"
- PATTERN conflict: Two routes have patterns that could match the same URLs (e.g., "/users/<id>" vs "/users/:id") - severity: "error"
- AMBIGUOUS conflict: Routes where registration order matters (e.g., "/items/<id>" and "/items/<name>") - severity: "warning"
- Each conflict entry MUST include: method, path, severity, involved_routes (with order and endpoint), and resolution_suggestion

Warning detection requirement (NEW):
- Detect routes with very similar paths that might be typos (Levenshtein distance < 3)
- Detect routes that might never be reached due to broader patterns registered earlier
- Detect routes without source attribution in production scenarios

Pattern analysis requirement (NEW):
- Calculate complexity score for each route (static=1.0, one param=2.0, multiple params=3.0+, regex=5.0+)
- Identify the most complex routes (top 5)
- Calculate average complexity per blueprint
- Detect potential performance bottlenecks (routes that would require many comparisons)

Determinism requirement:
- ALL lists (routes, conflicts, warnings) must be sorted in a stable, deterministic way
- Tie-breaking rules must be documented in code comments
- Re-running route_manifest() must produce identical output for identical input

Performance requirement (NEW):
- route_manifest() should complete in O(n²) time or better for n routes
- Document the algorithmic complexity in a docstring
- Include timing information in the summary (execution_time_ms)

The provided tests check only a minimum baseline.
Your implementation must be production-ready and handle edge cases gracefully.
