You may add new files only if explicitly required (this task requires run_tests.sh and README.md).
Do NOT introduce third-party runtime dependencies besides pytest for testing.

---

Feature: "Config Diff Explanation"

There are three configuration layers from lowest to highest priority:

1) base
2) env
3) override

Priority rule:
override > env > base

The function `explain_config_value` must return an Explanation object describing
how the final value of a configuration key is derived.

---

Rules:

1. Nested keys:
   - The key may be dot-separated, e.g. "db.timeout".
   - Each segment traverses dictionaries.
   - If any intermediate segment is missing or is not a dict,
     that layer treats the key as missing.

2. Explicit None:
   - If a layer defines the key with value None, the key is explicitly defined.
   - None is a valid value and must not be treated as missing.
   - The source must point to that layer.

3. Delete semantics:
   - The constant DELETE represents explicit deletion.
   - If the highest-priority layer that defines the key sets it to DELETE:
       - The final result is treated as missing.
       - final_value must be None.
       - source must be "missing".
       - All lower-priority values are suppressed.

4. overridden:
   - True if the key is defined in two or more layers among base/env/override.
   - Definition includes explicit None and DELETE.
   - Otherwise False.

5. override_chain:
   - A list of layer names that define the key.
   - Ordered from lowest to highest priority:
     ["base", "env", "override"].
   - Includes layers where the value is None or DELETE.
   - Missing everywhere results in an empty list.

Constraints:
